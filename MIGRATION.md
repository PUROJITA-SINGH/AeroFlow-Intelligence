# Railway to Render Migration

This project is configured for Render with a single Blueprint file: `render.yaml`.

## Target Services

- `aeroflow-db`: Render PostgreSQL 15, free plan.
- `aeroflow-api`: FastAPI backend, Docker runtime, free web service.
- `aeroflow-ui`: React/Vite frontend, Render Static Site.

Default placeholder URLs:

- Frontend: `https://aeroflow-ui.onrender.com`
- Backend API: `https://aeroflow-api.onrender.com`
- API health check: `https://aeroflow-api.onrender.com/health`

If Render changes either service slug during creation, update `CORS_ORIGINS` on `aeroflow-api` and `VITE_API_URL` on `aeroflow-ui`.

## Deploy With the Blueprint

1. Push this branch to GitHub.
2. In Render, choose **New +** -> **Blueprint**.
3. Connect `https://github.com/PUROJITA-SINGH/AeroFlow-Intelligence`.
4. Select the branch that contains `render.yaml`.
5. Review the free services:
   - PostgreSQL database: `aeroflow-db`
   - Web service: `aeroflow-api`
   - Static site: `aeroflow-ui`
6. Provide the prompted secret values:
   - `ADMIN_PASSWORD`
   - `OPERATIONS_PASSWORD`
   - `VIEWER_PASSWORD`
7. Apply the Blueprint.

Render injects `DATABASE_URL` into the backend from `aeroflow-db`. The app already normalizes `postgres://` URLs if Render ever provides that scheme.

## Migrations

The backend Docker image runs `Backend/prestart.sh` before starting Uvicorn. That script runs:

```sh
python -m alembic upgrade head
```

To run migrations manually from a Render shell:

```sh
cd /app
python -m alembic upgrade head
```

To run migrations locally against the Render database, copy the external database URL from the Render PostgreSQL dashboard and run:

```powershell
$env:DATABASE_URL = "postgresql://aeroflow:<password>@<external-host>:<port>/aeroflow"
cd Backend
python -m alembic upgrade head
```

## Seed Initial Users

The seed script creates these users if they do not already exist:

- `admin` with role `admin`
- `sensor_operator` with role `operations`
- `viewer` with role `viewer`

Recommended one-time seeding from a Render shell:

```sh
cd /app
ADMIN_PASSWORD='<strong-admin-password>' \
OPERATIONS_PASSWORD='<strong-operations-password>' \
VIEWER_PASSWORD='<strong-viewer-password>' \
python seed_admin.py
```

Alternative deployment-time seeding:

1. Set `ADMIN_PASSWORD`, `OPERATIONS_PASSWORD`, and `VIEWER_PASSWORD` on `aeroflow-api`.
2. Temporarily set `SEED_ADMIN=true`.
3. Redeploy `aeroflow-api`.
4. Set `SEED_ADMIN=false` again after the users are created.

## GitHub Actions

The workflow keeps backend checks, frontend build, Docker build checks, and security checks. Railway deployment was removed.

Render can deploy from the Blueprint directly. Optional deploy hooks are supported if you add these GitHub repository secrets:

- `RENDER_BACKEND_DEPLOY_HOOK_URL`
- `RENDER_FRONTEND_DEPLOY_HOOK_URL`

Without those secrets, the deploy job logs that Blueprint auto-deploy/manual sync should be used.

## Troubleshooting

- Backend fails with `CORS_ORIGINS must be set in production`: set `CORS_ORIGINS` to your exact frontend origin, for example `https://aeroflow-ui.onrender.com`.
- Frontend calls the wrong API: update `VITE_API_URL` on the static site and redeploy the frontend so Vite rebuilds with the new value.
- Login fails after reseeding: `seed_admin.py` is idempotent and skips existing users. Change passwords manually in the database or delete/recreate the user before rerunning the seed script.
- Migrations fail: verify `DATABASE_URL` points to the Render PostgreSQL database and run `python -m alembic upgrade head` from the `Backend` directory or from `/app` in the backend container.
- First request is slow: Render free web services can spin down when idle.
- WebSocket connection fails: use `wss://aeroflow-api.onrender.com/ws/live` from HTTPS pages, and confirm the backend service is awake.
- Static routes return 404 on refresh: confirm the static site route rewrite from `/*` to `/index.html` exists in Render.
